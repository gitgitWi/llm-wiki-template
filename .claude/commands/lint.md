대상: `$ARGUMENTS` (비어 있으면 `wiki/` 전체)

위키를 점검하고 **보고서를 낸다.** 발견한 것을 곧바로 고치지 말고, 먼저 분류해서 보여준다.

## 점검 항목

**구조**
- 고아 페이지 — 어떤 페이지에서도 링크되지 않은 문서
- 깨진 `[[링크]]` — 대상 파일이 없는 위키링크
- `index.md` 누락 — 실제 파일은 있는데 카탈로그에 없는 페이지 (반대 경우도)
- 원자성 위반 — 한 페이지가 여러 개념을 다루고 있어 쪼개야 하는 경우

**스키마**
- frontmatter 누락·오타 (특히 `visibility`, `type`, `domains`)
- `domains` 가 닫힌 어휘(`ai` `dev` `career` `product` `infra` `misc`) 밖의 값
- 파일명에 한글·공백·대문자가 섞인 경우
- `updated` 가 실제 마지막 수정과 어긋난 경우

**내용**
- 페이지 간 모순되는 주장
- 낡은 주장 — 시간에 민감한 내용인데 오래된 것 (버전, 가격, "최신" 표현)
- 커버리지 갭 — 여러 digest가 언급하지만 정작 페이지가 없는 개념

**공개 안전**
- `visibility: public` 문서가 `private` 문서를 `[[링크]]` 하고 있는 경우
- public 문서에 개인정보·회사 정보·원문 장문 복붙이 있는지

## 보고 형식

발견 항목을 **자동 수정 가능 / 승인 필요 / 보고만** 세 그룹으로 나눈다.

| 그룹 | 예 | 처리 |
|---|---|---|
| 자동 수정 | 깨진 링크, index 누락, frontmatter 오타, 날짜 불일치 | 사용자 확인 후 일괄 수정 |
| 승인 필요 | 페이지 분할·병합·삭제, 고아 페이지 처리 | 제안만, 개별 승인 |
| 보고만 | **산문 주장 간 모순**, 낡았을 가능성 | **위키에 확정해 넣지 않는다** |

마지막에 **다음에 넣으면 좋을 소스**와 **던져볼 만한 질문**을 제안한다.

작업 후 `.dev/log.md` 맨 위에 기록 (최신순):

```markdown
## [YYYY-MM-DD] lint | <대상>
- 점검 N건, 수정 M건, 보고 K건
```
